# 09 — Internationalization (English · Hindi · Urdu · Telugu)

## 1. Locales
| Code | Language | Script | Direction | UI font | Notes |
|---|---|---|---|---|---|
| `en` | English | Latin | LTR | Inter | Source language for all keys |
| `hi` | Hindi | Devanagari | LTR | Noto Sans Devanagari | |
| `ur` | Urdu | Arabic (Nastaliq) | **RTL** | Noto Nastaliq Urdu (lazy) | Full mirroring |
| `te` | Telugu | Telugu | LTR | Noto Sans Telugu | |
Default on first launch: best match of `navigator.languages` among these (e.g. `hi-IN` → `hi`, `ur-*` → `ur`, `te-*` → `te`), else `en` — but the user always confirms on the Language onboarding page.

## 2. Library & structure
- `i18next` + `react-i18next` + `i18next-icu` (ICU MessageFormat for plurals/select). Verify current versions/APIs in Phase 0.
- Files: `packages/i18n/locales/<locale>/<namespace>.json`; namespaces per feature (`common`, `onboarding`, `home`, `masjid`, `timings`, `announcements`, `hadith`, `dua`, `donations`, `chanda`, `videos`, `updates`, `qibla`, `settings`, `legal`, `errors`, `admin.*`, `super.*`).
- Namespaces lazy-loaded per route; the active locale's `common` + current route namespaces are precached by the SW.
- **Typed keys**: generate a `.d.ts` from `en` files so `t('home.nextPrayer')` is type-checked; unknown keys fail typecheck.
- Error codes from the API (`code`) map to `errors.<CODE>` keys.

## 3. Rules for keys & copy
- Keys are semantic (`donations.receivedReported`), never English sentences.
- No string concatenation; use ICU params: `"{count, plural, one {# new update} other {# new updates}}"`.
- Hindi/Urdu/Telugu plural forms: use ICU categories supported by CLDR for each locale; test with 0, 1, 2, 5, 21.
- Do not embed numbers/times/dates in translations manually — pass formatted values as params.
- Max lengths: give translators a `_meta.json` per namespace with context + max characters for tight UI (tabs, chips, buttons).
- `pnpm i18n:check` (CI): every key exists in all 4 locales, no extra keys, ICU syntax valid, identical placeholder sets across locales, no empty strings, no untranslated English in non-en files (heuristic: Latin-only strings > 3 words flagged unless whitelisted terms like "UPI", "QR").
- **Translation status**: Claude Code writes `en` and *draft* `hi`/`ur`/`te`. Every non-English string written by Claude Code is recorded in `packages/i18n/review/<locale>.csv` (key, en, draft) for a human translator to review. Production builds show a warning in the Phase report if unreviewed counts > 0 (owner decision whether to ship).
- Religious terms in English UI: Jamaat, Adhan, Jumu'ah, Bayan, Chanda, Inteqal, Dua, Ameen, Hadith, Ayah, Sehri, Iftar, Taraweeh, Eid — keep these spellings consistently (glossary in `packages/i18n/glossary.md` with the agreed native-script forms per locale, to be confirmed by the owner's translators).

## 4. Formatting (all via `packages/i18n/format.ts`, wrapping `Intl` — memoize formatters)
- Locale for `Intl`: `en-IN`, `hi-IN`, `ur-IN`, `te-IN`, always with `numberingSystem: 'latn'` (Latin digits everywhere — decided for clarity of times and amounts).
- Currency: `₹` + Indian grouping (`₹1,00,000`), no decimals unless non-zero paise.
- Times: 12-hour with AM/PM localized (`hour: 'numeric', minute: '2-digit', hourCycle: 'h12'`); strip shows time and AM/PM on separate lines (ref).
- Dates: short ("26 Sep"), medium ("26 Sep 2026"), with weekday ("Thu, 8 Oct").
- Relative time: `Intl.RelativeTimeFormat` with `numeric: 'auto'` ("yesterday"); switch to date after 6 days.
- Hijri: `Intl.DateTimeFormat('<locale>-u-ca-islamic-umalqura-nu-latn', { day, month: 'long', year })` + offset logic from `packages/domain/hijri`. Month names come from Intl; if a locale's Intl output is poor/missing on a target browser, fall back to our own month-name table per locale (test on Android Chrome + iOS Safari).
- Countdown: "2h 18m left" style via ICU message with hours/minutes params.
- Lists: `Intl.ListFormat`.
- Sorting/search: `Intl.Collator` per locale; search normalizes (case-fold, remove diacritics/harakat for Arabic script search in library).

## 5. RTL (Urdu)
- `<html lang="ur" dir="rtl">` set before first paint (read locale from IndexedDB-mirrored `localStorage` key `mc.locale` for synchronous boot; IndexedDB remains the source of truth).
- Layout uses logical properties only (Tailwind `ms-/me-/ps-/pe-/start-/end-/text-start/text-end`, `rounded-s-*`). ESLint/Stylelint rule bans physical `left/right/ml/mr/pl/pr` utilities in app code.
- Mirrored: chevrons/back arrows, swipe-back edge and direction, stack push direction, carousels' start side, progress bars fill direction, tab order (browser handles via flex direction), sheet drag affordances unaffected.
- **Not mirrored**: Arabic religious text blocks (always `dir="rtl"`, they're RTL anyway), Latin-only strings like VPA/URLs/phone numbers (wrap in `<bdi>` / `dir="ltr"`), times and amounts (use `<bdi>`), media player timeline, compass dial, QR codes.
- Charts (Chanda) **are** mirrored in RTL so time flows right-to-left, consistent with reading direction (default; the owner may reverse this in Phase 5).
- Icons that imply direction are flipped with `rtl:-scale-x-100`; others are not.
- Mixed-direction strings (Urdu text with masjid names in Latin) use `unicode-bidi: plaintext` on paragraphs.
- Visual regression baselines for every screen in `ur`.

## 6. Fonts & performance
- Self-host via `@fontsource-variable/*` (or equivalent) packages; subset to needed glyph ranges; `unicode-range` declarations so the browser downloads only what's used.
- Preload only the active-locale UI font; Amiri loaded when a screen with Arabic text renders (Home "Recent Updates" may show Arabic → load on idle after first paint).
- `size-adjust`/`ascent-override` fallback metrics to avoid CLS when fonts swap.
- Noto Nastaliq Urdu is large: load only for `ur`, show system Urdu fallback first (`font-display: swap`).

## 7. Content languages vs UI language
- UI strings follow the device locale.
- Template-based posts render in the musalli's locale (params formatted per locale).
- Free-text posts render as typed, with `lang` attribute = `content_locale` (and `dir` auto) so fonts/shaping are correct even inside another-language UI.
- Library content: translation in UI locale if present; else English with a small "English" tag; Arabic always shown.
- Push notifications: localized per device locale at fan-out (01 §5.3).

## 8. Admin app specifics
- Admin UI locale chosen at invite acceptance, stored on `admin_users.ui_locale`, switchable anytime.
- Admin strings favour very short words + icons; avoid jargon ("Publish" → consider "Send to people" — final wording by translators).
- Template picker labels are short (≤ 18 chars) with icons; full text visible in preview.

## 9. Legal documents
- `packages/i18n/legal/<locale>/{privacy,terms,content-policy,grievance}.md` with front-matter `version`, `status: draft|reviewed`. Rendered by the legal reader. Production build refuses `status: draft` (05 §10).
