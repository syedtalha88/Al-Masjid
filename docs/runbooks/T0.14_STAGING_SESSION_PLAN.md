## Topology on the one VPS (DECISIONS #42, #54)

```
Cloudflare ──443 (only Cloudflare IPs: ufw + DOCKER-USER)──► mc-edge: HAProxy, TCP mode, routes by SNI
                                                               │  app-staging./admin-staging./media-staging. ─► mc-staging web (Caddy, TLS + client cert)
                                                               │  app./admin./media.                         ─► mc-production web (Caddy, TLS + client cert)
                                                               └  anything else → connection closed
mc-staging:    web · api-public ×2 · api-admin ×2 · worker · redis      (own network, own env dir, own Redis ACL)
mc-production: same, separate everything (started in Phase 9)
```
- The edge router never decrypts: each environment's Caddy terminates TLS with its own Origin CA certificate and
  verifies Cloudflare's client certificate (Authenticated Origin Pulls), exactly as the Caddyfile does today
  (`CADDY_TLS=origin`). The router holds no keys.
- No port 80 on the server: Cloudflare's "Always Use HTTPS" redirects; Cloudflare connects to the origin on 443 only.
- Client IPs for rate limits still come from `CF-Connecting-IP` (`TRUSTED_PROXY_MODE=cloudflare`).

## Release delivery (DECISIONS #27, #55, PROGRESS F25)

```
CI (main, green) → Release to staging: images → GHCR (digests) → release-manifest.json
                 → signed with the staging key (ssh-keygen -Y sign, namespace masjid-connect-release)
                 → uploaded to the GitHub pre-release "staging-current" (manifest + .sig, replaced each time)
VPS deploy timer (every minute, root — #56, #59): curl the two files → ssh-keygen -Y verify against allowed_signers
                 → newer than everything deployed? → this environment's checkout to the signed commit → compose
                   hardening policy → pull by digest → migrate (later) → rolling replacement with health waits
                   (logs archived first) → smoke checks → releases.log (rollback: DEPLOY.md §3)
```
No credential that can reach the VPS exists in GitHub. A stolen GitHub token can publish only manifests the server
rejects (no valid signature, or not newer than what runs — replay protection); at worst it can delete the release
assets, which pauses updates until the next CI release.
